## 2. Daftar Endpoint yang Diimplementasikan

Seluruh endpoint REST API `v1` telah diimplementasikan sesuai kontrak `v0.2.0-D-A-api-specification.md`:

### A. Health & Verification Metadata
| Method | Path | Auth | Fungsi |
|---|---|---|---|
| `GET` | `/v1/health` (alias `/health`) | Public | Mengembalikan status layanan, `product_id` (`com.stockstudiopro.desktop`), `signing_kid` aktif, `public_key_base64` (32-byte Ed25519 public key), dan `server_time`. |

### B. Public Client Endpoints (Desktop Application)
| Method | Path | Auth | Fungsi & Perilaku Utama |
|---|---|---|---|
| `POST` | `/v1/licenses/activate` | `license_key` di body + header `X-Client-Product` | Validasi format `SSPRO-XXXX-XXXX-XXXX-XXXX`, verifikasi `HMAC-SHA256` key hash, idempotent re-activation, *reinstall recovery* otomatis jika `device_fingerprint` cocok pada perangkat yang sama, alokasi slot atomik (`active_devices_count < device_limit`), serta penerbitan `activation_token` (`ssact_...`) dan `lease_token` bertanda tangan **Ed25519**. |
| `POST` | `/v1/licenses/validate` | `Authorization: Bearer ssact_...` | Verifikasi hash `activation_token`, pemeriksaan kecocokan `device_id` dan `device_fingerprint`, transisi otomatis `expired` jika lisensi `subscription` melewati `expires_at` / `grace_until`, pembaruan heartbeat, dan penerbitan `lease_token` Ed25519 baru (7 hari, dipotong oleh `expires_at` untuk langganan). |
| `POST` | `/v1/licenses/deactivate` | `Bearer ssact_...` atau `license_key` | Menonaktifkan perangkat secara idempoten (mendukung *self-deactivation* maupun pelepasan perangkat lama yang hilang menggunakan `license_key` + `target_activation_id`) dan mengurangi `active_devices_count` secara atomik. |
| `GET` | `/v1/licenses/devices` | `Bearer ssact_...` atau `X-License-Key` | Menampilkan daftar perangkat aktif yang terikat pada lisensi beserta `device_limit`, `devices_used`, dan penanda `is_current_device`. |

### C. Administrative & Provider-Independent Billing Endpoints
| Method | Path | RBAC Role | Fungsi & Perilaku Utama |
|---|---|---|---|
| `POST` | `/v1/admin/licenses` | `super_admin`, `billing_system` | Menerbitkan lisensi baru (`perpetual` dengan `billing_interval = "lifetime"` & `expires_at = null`, atau `subscription` dengan `billing_interval = "monthly" \| "yearly"`). Mendukung `Idempotency-Key` dan mengembalikan plaintext `license_key` hanya satu kali saat pembuatan. |
| `GET` | `/v1/admin/licenses/:license_id` | `super_admin`, `support_admin`, `billing_system`, `read_only` | Mengambil detail lisensi, data `billing_subscriptions`, seluruh riwayat `activations`, dan 50 catatan audit `license_events` terbaru. |
| `PATCH` | `/v1/admin/licenses/:license_id` | `super_admin`, `support_admin` | Memperbarui `device_limit` (memastikan tidak lebih kecil dari `active_devices_count` saat ini), `customer_email`, `customer_name`, `notes`, dan `entitlements`. |
| `POST` | `/v1/admin/licenses/:license_id/suspend` | `super_admin`, `support_admin` | Membekukan sementara lisensi (`status = 'suspended'`) beserta pencatatan alasan dan audit event `license.suspended`. |
| `POST` | `/v1/admin/licenses/:license_id/reinstate` | `super_admin`, `support_admin` | Mengaktifkan kembali lisensi yang di-suspend ke `active` (atau `pending_activation` jika belum pernah diaktifkan). |
| `POST` | `/v1/admin/licenses/:license_id/revoke` | `super_admin`, `billing_system` | Mencabut lisensi secara permanen (`status = 'revoked'`), mencabut semua aktivasi perangkat aktif (`status = 'revoked'`), dan mereset `active_devices_count = 0`. |
| `POST` | `/v1/admin/licenses/:license_id/renew` | `super_admin`, `billing_system` | Memperpanjang masa aktif lisensi `subscription` melalui pencatatan idempoten di `billing_events` (`UNIQUE(provider, provider_event_id)`). |
| `DELETE` | `/v1/admin/licenses/:license_id/devices/:activation_id` | `super_admin`, `support_admin` | Melepaskan paksa (*force-deactivate*) slot perangkat tertentu secara idempoten. |
| `POST` | `/v1/billing/webhooks/:provider` | `X-Webhook-Signature` (HMAC-SHA256) | Lapisan webhook independen payment gateway. Memverifikasi tanda tangan HMAC payload, mencatat ke `billing_events` secara idempoten, dan memproses event kanonis (`payment.succeeded`, `subscription.renewed`, `payment.failed`, `subscription.canceled`, `payment.refunded`, `payment.chargeback`). |

## 3. Skema Database & Migrasi Cloudflare D1

File migrasi [`workers/license-api/migrations/0001_initial_license_schema.sql`](file:///e:/2.%20Microstock/TOOL/flowpilot-main/flowpilot-main/workers/license-api/migrations/0001_initial_license_schema.sql) mengimplementasikan 9 tabel sesuai `v0.2.0-D-A-database-schema.sql`:

1. `signing_keys`: Metadata kunci publik Ed25519 (`kid`, `public_key_base64`, `status`).
2. `admin_api_keys`: Kredensial admin yang di-hash dengan `HMAC-SHA256(ADMIN_TOKEN_PEPPER, token)` dan RBAC role.
3. `licenses`: Tabel entitlement terpadu untuk `perpetual` dan `subscription` dengan `CHECK` constraint lintas kolom yang menjamin `perpetual` memiliki `expires_at IS NULL` dan `subscription` memiliki `expires_at IS NOT NULL`, serta penjaga kuota `CHECK (active_devices_count >= 0 AND active_devices_count <= device_limit)`.
4. `devices`: Profil perangkat unik (`id` UUID v4, `device_fingerprint` SHA-256 hex, `device_name`, `platform`).
5. `activations`: Relasi pengikatan perangkat ke lisensi dengan dua partial unique index (`idx_activations_unique_active_device` dan `idx_activations_unique_active_fingerprint` `WHERE status = 'active'`).
6. `billing_subscriptions`: Rekaman langganan yang terpisah dari spesifikasi payment gateway tertentu (`UNIQUE(provider, external_subscription_id)`).
7. `billing_events`: Ledger idempoten seluruh transaksi pembayaran/webhook (`UNIQUE(provider, provider_event_id)`).
8. `license_events`: Audit trail *append-only* untuk seluruh siklus hidup lisensi.
9. `rate_limit_buckets`: Penyimpanan counter pembatasan laju (*rate limiting*) dan *lockout* per IP hash dan `key_prefix`.

### Rincian Skenario yang Diuji pada `tests/license-api.test.ts`:
1. **Health & Public Key Metadata:** Memastikan `/v1/health` mengembalikan `product_id`, `signing_kid`, dan `public_key_base64`.
2. **Perpetual License Full Lifecycle & Ed25519 Verification:** Penerbitan lisensi `perpetual` (`lifetime`), verifikasi bahwa D1 tidak menyimpan plaintext key (`key_hash` 64-char hex), aktivasi perangkat, verifikasi tanda tangan kriptografis Ed25519 pada `lease_token`, penolakan `lease_token` yang dimodifikasi (*tampered payload*), dan pembaruan lease saat `validate`.
3. **Atomic Device Limit (`default = 2`), Reinstall Recovery, & Deactivation:** Aktivasi perangkat ke-1, simulasi reinstall pada perangkat ke-1 (UUID baru + `device_fingerprint` sama → *idempotent rebind* tetap menggunakan `1/2` slot), aktivasi perangkat ke-2 (`2/2`), penolakan perangkat ke-3 dengan `409 DEVICE_LIMIT_REACHED`, pengecekan daftar perangkat via `GET /v1/licenses/devices`, pelepasan slot via `POST /v1/licenses/deactivate` (termasuk pengujian idempotensi panggilan ulang), diikuti aktivasi sukses perangkat ke-3.
4. **Subscription Lifecycle & Idempotent Webhook Renewal:** Penerbitan langganan `monthly` yang akan berakhir dalam 4 hari, verifikasi bahwa `lease.exp` otomatis dipotong (*capped*) pada `expires_at`, simulasi waktu melewati `expires_at` yang menghasilkan `403 LICENSE_EXPIRED`, pemrosesan webhook `payment.succeeded` bertanda tangan HMAC untuk memperpanjang langganan, pengujian replay webhook dengan `event_id` yang sama (`idempotent_replay: true`), dan verifikasi bahwa lisensi kembali `active`.
5. **Admin Operations & RBAC:** Penolakan role `read_only` saat mencoba menerbitkan lisensi (`403 FORBIDDEN_ROLE`), pembekuan (`suspend` → `403 LICENSE_SUSPENDED`), pemulihan (`reinstate` → `active`), pelepasan paksa perangkat oleh admin (`DELETE .../devices/:id` → `403 ACTIVATION_REVOKED`), dan pencabutan permanen (`revoke` → `403 LICENSE_REVOKED`).
6. **Security Controls:** Penolakan header produk legacy Flowpilot (`X-Client-Product: com.flowpilot.desktop` → `400 PRODUCT_MISMATCH`), penolakan *clock skew* $> 300\text{ detik}$ (`400 CLOCK_SKEW_TOO_LARGE`), dan penegakan *rate limit lockout* (`429 RATE_LIMITED` + header `Retry-After`).
7. **Admin Idempotency, PATCH Quota, Manual Renewal, & Refund/Cancel Webhooks:** Penolakan duplikasi `Idempotency-Key` pada pembuatan lisensi (`409 IDEMPOTENCY_CONFLICT`), peningkatan `device_limit` via `PATCH`, penolakan penurunan `device_limit` di bawah jumlah perangkat aktif saat ini, perpanjangan manual idempoten via `/v1/admin/licenses/:id/renew`, penolakan tanda tangan webhook palsu (`401`), pembatalan akhir periode (`subscription.canceled`), serta pencabutan otomatis saat terjadi `payment.refunded`.

## 5. Instruksi Menjalankan Worker Secara Lokal

Untuk menjalankan StockStudio Pro License API secara lokal di mesin pengembangan:

```powershell
# 1. Masuk ke direktori Worker
cd workers/license-api

# 2. Instal dependensi (jika belum)
npm install

# 3. Buat file .dev.vars lokal sementara (gitignored) dengan Ed25519 keypair & HMAC peppers acak
npm run dev:setup

# 4. Terapkan migrasi schema database ke Cloudflare D1 lokal
npm run db:migrate:local

# 5. Jalankan test suite otomatis atau jalankan server pengembangan lokal (http://127.0.0.1:8787)
npm test
npm run dev
```

File `.dev.vars` yang dihasilkan oleh `npm run dev:setup` bersifat lokal dan sudah diabaikan oleh `.gitignore` (`workers/license-api/.gitignore` dan `.gitignore` root), sehingga tidak ada private key atau secret yang pernah masuk ke repositori Git.

## 6. Kebutuhan Konfigurasi Cloudflare & Daftar Pekerjaan yang Menunggu Akun / Domain / Secret

Ketika akun Cloudflare siap digunakan untuk staging (`*.workers.dev`) atau produksi:

1. **Autentikasi Wrangler & Pembuatan Database D1 Remote:**
   ```powershell
   cd workers/license-api
   npx wrangler login
   npx wrangler d1 create stockstudio-pro-licenses-staging
   ```
   Salin `database_id` yang dihasilkan ke bagian `[[env.staging.d1_databases]]` pada `workers/license-api/wrangler.toml`.
2. **Penerapan Migrasi D1 ke Staging:**
   ```powershell
   npm run db:migrate:staging
   ```
3. **Konfigurasi Cloudflare Secrets (Staging / Production):**
   ```powershell
   npx wrangler secret put LICENSE_KEY_PEPPER --env staging
   npx wrangler secret put ADMIN_TOKEN_PEPPER --env staging
   npx wrangler secret put IP_HASH_SALT --env staging
   npx wrangler secret put LICENSE_SIGNING_PRIVATE_KEY_JWK --env staging
   npx wrangler secret put LICENSE_SIGNING_PUBLIC_KEY_BASE64 --env staging
   npx wrangler secret put BILLING_WEBHOOK_SECRETS_JSON --env staging
   ```
4. **Item yang Masih Menunggu Keputusan Eksternal Sebelum Go-Live Produksi:**
   - **Akun Cloudflare & `database_id` D1 Remote:** Diperlukan untuk deploy ke `*.workers.dev` staging/production.
   - **Domain Produksi Resmi:** Setelah domain ditentukan, tambahkan `routes` atau `custom_domains` pada `[env.production]` di `wrangler.toml`.
   - **Pasangan Kunci Ed25519 Produksi Resmi:** Public key 32-byte (`LICENSE_SIGNING_PUBLIC_KEY_BASE64`) dari environment produksi nantinya akan disematkan sebagai konstanta verifikasi (`VERIFYING_KEYS`) di Rust desktop client pada `TASK D-C`.
