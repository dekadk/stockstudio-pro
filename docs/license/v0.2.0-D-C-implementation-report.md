## 2. Endpoint API yang Terhubung

Seluruh request dari `src-tauri/src/license_store.rs` menyertakan header standar:
`Accept: application/json`, `User-Agent: StockStudioPro/0.2.0 (windows; x86_64)`, `X-Client-Product: com.stockstudiopro.desktop`, `X-Client-Version: 0.2.0`, `X-Request-Timestamp`, dan `X-Request-Nonce` (UUID v4).

| Tauri Command | Endpoint Worker v1 | Autentikasi & Perilaku |
|---|---|---|
| `activate_license` | `POST /v1/licenses/activate` | Mengirim `license_key` dan objek `device` (`device_id`, `device_fingerprint`, `device_name`, `platform`, `os_version`, `arch`, `app_version`). Memverifikasi `lease_token` Ed25519 sebelum menyimpan `license-key`, `activation-token`, `clock-anchor` di Windows Credential Manager (`StockStudioPro`) dan `license-state.json` di `AppLocalData`. |
| `validate_license` | `POST /v1/licenses/validate` | Mengirim `Authorization: Bearer ssact_...` + identitas perangkat. Memverifikasi `lease_token` baru. Jika terjadi penolakan terminal (`LICENSE_REVOKED`, `LICENSE_SUSPENDED`, `LICENSE_EXPIRED`, `ACTIVATION_REVOKED`, `DEVICE_MISMATCH`, `UNAUTHORIZED_TOKEN`), cache lokal langsung dihapus. Jika terjadi timeout jaringan atau error `5xx`, mengevaluasi *offline grace period* 7 hari. |
| `deactivate_license` | `POST /v1/licenses/deactivate` | Mendukung *self-deactivation* via `Bearer ssact_...` maupun pelepasan perangkat lain via `target_activation_id` + `license_key`. Saat perangkat sendiri dinonaktifkan, kredensial lisensi lokal dihapus sambil **tetap mempertahankan `device-id`** di Credential Manager. |
| `list_license_devices` | `GET /v1/licenses/devices?device_id=<uuid>` | Menggunakan `Bearer ssact_...` (atau header `X-License-Key` saat diperlukan dari layar aktivasi) untuk mengambil daftar perangkat aktif dan kuota slot perangkat. |
| `get_device_id` | Lokal (`Keyring` + `AppLocalData`) | Mengambil/membuat UUID v4 perangkat yang di-anchor di Windows Credential Manager (`StockStudioPro / device-id`). |
| `get_license_state` | Lokal (`license-state.json` + Verifikasi Ed25519) | Hanya mengembalikan `Some(LicenseState)` apabila `lease_token` lolos verifikasi tanda tangan Ed25519 dan cocok dengan `device_id` serta `device_fingerprint` perangkat ini. |
| `clear_license_state` | Lokal (`Keyring` + `AppLocalData`) | Menghapus `activation-token`, `license-key`, dan `license-state.json` tanpa menghapus `device-id`. |

## 3. Mekanisme Keamanan yang Diterapkan di Client Rust

1. **Verifikasi Ed25519 Wajib Tanpa Bypass:**
   - Menggunakan `ed25519-dalek` v2 (`VerifyingKey::from_bytes` + `verify`) atas `v1.<base64url_payload>`.
   - Private key **tidak pernah ada** di dalam kode maupun binary desktop; client hanya menerima public key 32-byte base64 (`STOCKSTUDIO_LICENSE_PUBLIC_KEY_BASE64` / `EMBEDDED_VERIFYING_KEYS`).
   - Memverifikasi klaim wajib: `ver == 1`, `iss == "stockstudiopro-license-server"`, `aud == "com.stockstudiopro.desktop"`, serta kecocokan `device_id` dan `device_fingerprint`.
2. **Windows Credential Manager (`keyring` v3, Service `"StockStudioPro"`):**
   - Menyimpan `"device-id"`, `"license-key"`, `"activation-token"`, dan `"clock-anchor"` secara terpisah dari file JSON non-rahasia.
3. **Offline Grace Period (7 Hari) & Clock Rollback Guard (Toleransi 5 Menit):**
   - Saat offline atau server mengembalikan `5xx`, client mengizinkan akses hanya jika `lease_token` Ed25519 valid, `now_utc <= min(lease.exp, lease.iat + 7 hari)`, dan (untuk `subscription`) `now_utc < expires_at`.
   - Jika `now_utc + 300s < lease.iat` atau `now_utc + 300s < clock_anchor`, client menolak mode offline dengan error `"System Clock Rollback Detected"`.
4. **Penolakan Host Legacy Flowpilot & HTTP Non-Lokal:**
   - `validate_api_base_url` menolak URL yang mengandung `flowpilot` dan mewajibkan `https://` untuk semua host non-loopback (`http://127.0.0.1` / `localhost` hanya diizinkan pada debug build untuk Wrangler dev lokal).

### Rincian 7 Test Baru pada `src-tauri/src/license_store.rs`:
1. `activates_perpetual_license_verifies_ed25519_and_persists_credentials`: Aktivasi lisensi `perpetual`, verifikasi tanda tangan Ed25519, penyimpanan `activation-token` & `license-key`, serta verifikasi pembacaan kembali `LicenseState` yang kompatibel dengan field lama.
2. `activates_subscription_license_and_tracks_period_and_expiry`: Aktivasi lisensi `subscription` (`monthly`) dan verifikasi `expires_at`, `current_period_end`, dan `lifetime == false`.
3. `handles_expired_suspended_revoked_and_device_limit_errors`: Pemetaan respons error `403 LICENSE_EXPIRED`, `403 LICENSE_SUSPENDED`, `403 LICENSE_REVOKED`, dan `409 DEVICE_LIMIT_REACHED`.
4. `lists_devices_and_deactivates_preserving_device_id`: Pengambilan daftar perangkat (`list_license_devices`) dan deaktivasi (`deactivate_license`) yang membersihkan token lisensi lokal sambil mempertahankan `device-id`.
5. `rejects_invalid_signature_tampered_lease_expired_lease_and_clock_rollback`: Evaluasi *offline grace period* valid (hari ke-3), penolakan payload/tanda tangan palsu, penolakan *clock rollback* $> 5\text{ menit}$, dan penolakan *offline grace* yang lewat 7 hari (hari ke-8).
6. `falls_back_to_offline_grace_on_5xx_and_timeout_but_revokes_on_403_terminal`: Fallback ke *offline grace* pada respons server `503` dan network timeout, namun penghapusan cache lokal secara langsung pada respons terminal `403 LICENSE_REVOKED`.
7. `validates_api_url_and_rejects_legacy_flowpilot_or_insecure_remote_http`: Validasi HTTPS-only untuk host remote, izin loopback di debug build, dan penolakan host legacy `flowpilot`.

## 5. Konfigurasi Development Lokal (Menghubungkan Desktop ke Worker Lokal)

Untuk menguji aplikasi desktop Tauri secara langsung terhadap Worker D1 lokal dari `TASK D-B`:

1. Jalankan Worker lokal di terminal 1 (`http://127.0.0.1:8787`):
   ```powershell
   cd workers/license-api
   npm run dev:setup
   npm run db:migrate:local
   npm run dev
   ```
   Catat nilai `LICENSE_SIGNING_PUBLIC_KEY_BASE64` yang ditampilkan oleh `npm run dev:setup` (atau dari `GET http://127.0.0.1:8787/v1/health`).
2. Jalankan aplikasi desktop di terminal 2 dengan menyuntikkan URL Worker lokal dan public key verifikasi:
   ```powershell
   $env:STOCKSTUDIO_LICENSE_API_URL = "http://127.0.0.1:8787"
   $env:STOCKSTUDIO_LICENSE_PUBLIC_KEY_BASE64 = "<PUBLIC_KEY_BASE64_DARI_WORKER_LOKAL>"
   $env:STOCKSTUDIO_LICENSE_SIGNING_KID = "sspro-ed25519-dev-01"
   npm run tauri dev
   ```

## 6. Keterbatasan yang Masih Ada

1. **Public Key Produksi Belum Disematkan di `EMBEDDED_VERIFYING_KEYS`:**
   - Karena pasangan kunci Ed25519 produksi Cloudflare Secrets dan domain/URL produksi belum diterbitkan oleh pemilik produk, `EMBEDDED_VERIFYING_KEYS` saat ini masih kosong dan release build mewajibkan variabel compile-time `STOCKSTUDIO_LICENSE_API_URL` serta `STOCKSTUDIO_LICENSE_PUBLIC_KEY_BASE64`.
2. **Pengujian GUI End-to-End Desktop + Worker Hidup:**
   - Integrasi protokol HTTP, Ed25519, D1, dan state client telah diverifikasi melalui 7 test Worker Miniflare D1 (`TASK D-B`) dan 7 test Rust mock-HTTP + kriptografi (`TASK D-C`). Uji GUI penuh di jendela WebView2 (aktivasi nyata -> transisi ke dashboard -> runtime test `C-B-B` yang tertunda) siap dijalankan pada fase berikutnya (`TASK D-D` / `D-E`).
