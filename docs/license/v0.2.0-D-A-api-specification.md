# StockStudio Pro v0.2.0-D-A: License REST API Specification (`v1`)

- **Produk:** StockStudio Pro (`com.stockstudiopro.desktop`)
- **Versi API:** `v1`
- **Base URL Placeholder:** `https://license-api.stockstudiopro.invalid` *(konfigurasi melalui environment/build variable `STOCKSTUDIO_LICENSE_API_URL` hingga domain resmi ditetapkan)*
- **Protokol:** HTTPS (TLS 1.2 / TLS 1.3 wajib; HTTP plaintext ditolak dengan `400` / redirect dinonaktifkan untuk POST)
- **Content-Type:** `application/json; charset=utf-8`

---

## 1. Konvensi Umum, Header, & Format Token

### 1.1 Header Standar Request Client

| Header | Wajib | Contoh | Deskripsi |
|---|---|---|---|
| `Content-Type` | Ya (POST/PATCH) | `application/json` | Format body JSON. |
| `Accept` | Ya | `application/json` | Format respons JSON. |
| `User-Agent` | Ya | `StockStudioPro/0.2.0 (windows; x86_64)` | Identitas client Tauri Rust. |
| `X-Client-Product` | Ya | `com.stockstudiopro.desktop` | Identifier aplikasi wajib; request dengan identifier lain (mis. Flowpilot) ditolak dengan `400 PRODUCT_MISMATCH`. |
| `X-Client-Version` | Ya | `0.2.0` | Versi semver aplikasi desktop. |
| `X-Request-Timestamp` | Ya | `1795190400` | Waktu epoch UTC dalam detik saat request dikirim. |
| `X-Request-Nonce` | Ya | `8a1f3e72-4d9c-4e1a-9b2f-1c5d7e9a0b3c` | UUID v4 unik per request untuk pencegahan replay. |
| `Idempotency-Key` | Opsional (Disarankan pada POST mutasi) | `5f4dcc3b-5aa7-465d-861d-8327deb882cf` | UUID v4 untuk menjamin operasi aktivasi/pembuatan lisensi idempoten. |
| `Authorization` | Kondisional | `Bearer ssact_...` atau `Bearer ssadm_...` | Token aktivasi perangkat (untuk `validate`, `deactivate`, `devices`) atau token Admin API (untuk `/v1/admin/*`). |

### 1.2 Struktur Signed Entitlement Lease (`lease` & `lease_token`)

Setiap respons sukses dari `POST /v1/licenses/activate` dan `POST /v1/licenses/validate` mengembalikan:
1. Objek JSON `lease` (untuk inspeksi langsung).
2. String `lease_token` berformat:
   ```text
   v1.<base64url_nopad(utf8_json_lease_payload)>.<base64url_nopad(ed25519_signature_64_bytes)>
   ```

> - `"current_period_start": null`
> - `"current_period_end": null`
> - `"exp"` dan `"offline_grace_until"` tetap `iat + 7 hari` (masa berlaku lease offline sebelum client perlu menyapa server kembali).

### 1.3 Skema Error Standar & Katalog Error Code

Seluruh respons error (`4xx` dan `5xx`) menggunakan amplop JSON seragam:
```json
{
  "ok": false,
  "error": {
    "code": "DEVICE_LIMIT_REACHED",
    "message": "Maximum active device limit (2) reached for this license.",
    "retryable": false,
    "details": {
      "device_limit": 2,
      "devices_used": 2
    }
  },
  "request_id": "req_01JDF90123456789ABCDEFGHJK",
  "server_time": "2026-11-20T16:00:00Z"
}
```

**Katalog Error Code Resmi:**

| Error Code | HTTP Status | Terminal bagi Cache Lokal? | Deskripsi |
|---|---|---|---|
| `INVALID_REQUEST` | `400` | Tidak | Payload JSON rusak, field wajib hilang, atau format UUID/hash tidak valid. |
| `PRODUCT_MISMATCH` | `400` | Tidak | Header `X-Client-Product` bukan `com.stockstudiopro.desktop`. |
| `CLOCK_SKEW_TOO_LARGE` | `400` | Tidak | Selisih `X-Request-Timestamp` dengan waktu server $> 300\text{ detik}$. |
| `INVALID_LICENSE_KEY` | `401` | Ya | Format kunci tidak valid atau hash kunci tidak ditemukan di D1. |
| `UNAUTHORIZED_TOKEN` | `401` | Ya | `activation_token` atau `admin_api_key` tidak valid / sudah kedaluwarsa. |
| `LICENSE_EXPIRED` | `403` | Ya | Lisensi `subscription` sudah melewati `expires_at` (dan melewati masa `past_due`). |
| `LICENSE_SUSPENDED` | `403` | Ya | Lisensi dibekukan sementara oleh administrator. |
| `LICENSE_REVOKED` | `403` | Ya | Lisensi dicabut permanen (refund / chargeback / abuse). |
| `ACTIVATION_REVOKED` | `403` | Ya | Perangkat ini telah dinonaktifkan dari lisensi tersebut (oleh pengguna atau admin). |
| `DEVICE_MISMATCH` | `403` | Ya | `device_id` atau `device_fingerprint` tidak cocok dengan `activation_token` yang dikirim. |
| `ACTIVATION_NOT_FOUND` | `404` | Ya | ID aktivasi atau perangkat tidak ditemukan pada lisensi ini. |
| `LICENSE_NOT_FOUND` | `404` | Tidak | ID lisensi tidak ditemukan (endpoint admin). |
| `DEVICE_LIMIT_REACHED` | `409` | Tidak | Jumlah perangkat aktif sudah mencapai `device_limit` (`active_devices_count >= device_limit`). |
| `IDEMPOTENCY_CONFLICT` | `409` | Tidak | `Idempotency-Key` yang sama dikirim dengan payload berbeda. |
| `RATE_LIMITED` | `429` | Tidak | Batas percobaan request terlampaui (`Retry-After` disertakan pada header). |
| `INTERNAL_ERROR` | `500` | Tidak | Kesalahan internal server / D1 (client berhak masuk ke *offline grace period*). |
| `SERVICE_UNAVAILABLE` | `503` | Tidak | Maintenance sementara (client berhak masuk ke *offline grace period*). |

## 2. Public Client Endpoints (Desktop Application)

### 2.1 `POST /v1/licenses/activate`
Mengaktifkan kunci lisensi pada perangkat saat ini, mengikat perangkat (`device binding`), dan menerbitkan `activation_token` beserta `lease_token` bertanda tangan Ed25519.

- **Autentikasi:** Kunci lisensi (`license_key`) di dalam body request.
- **Aturan Validasi:**
  1. `license_key` dinormalisasi (trim, uppercase) dan harus cocok dengan pola `^SSPRO-[A-HJ-NP-TV-Z0-9]{4}-[A-HJ-NP-TV-Z0-9]{4}-[A-HJ-NP-TV-Z0-9]{4}-[A-HJ-NP-TV-Z0-9]{4}$`.
  2. `device.device_id` wajib UUID v4 valid.
  3. `device.device_fingerprint` wajib hex SHA-256 64 karakter lowercase.
  4. `device.device_name` maksimal 120 karakter (disanitasi dari karakter kontrol).
  5. Lisensi harus berstatus `pending_activation`, `active`, atau `past_due`.
  6. Jika `license_type == "subscription"`, waktu server saat ini harus $< \text{coalesce}(\text{grace\_until}, \text{expires\_at})$.
- **Perilaku Idempotensi & Re-install:**
  - Jika perangkat dengan `device_id` yang sama **atau** `device_fingerprint` yang sama sudah memiliki aktivasi berstatus `active` pada lisensi tersebut, server **tidak menambah** slot perangkat baru. Server memperbarui `device_id` (jika reinstall mengubah UUID namun fingerprint tetap sama), memperbarui `last_seen_at`, merotasi `activation_token`, dan mengembalikan `200 OK`.
  - Jika perangkat benar-benar baru dan `active_devices_count < device_limit`, server menambah slot secara atomik dan mengembalikan `200 OK` (atau `201 Created`).
  - Jika perangkat baru dan `active_devices_count >= device_limit`, server mengembalikan `409 DEVICE_LIMIT_REACHED` beserta daftar ringkas perangkat aktif agar pengguna dapat memilih perangkat mana yang ingin dinonaktifkan.

### 2.2 `POST /v1/licenses/validate`
Memvalidasi aktivasi perangkat yang sudah ada, memperbarui heartbeat `last_validated_at` / `last_seen_at`, dan menerbitkan `lease_token` Ed25519 baru untuk 7 hari ke depan (dipotong oleh `expires_at` untuk langganan).

- **Autentikasi:** Header `Authorization: Bearer ssact_...` (atau fallback `license_key` di body jika migrasi dari state lama).
- **Aturan Validasi:**
  1. Memverifikasi hash `activation_token` di tabel `activations` (`status = 'active'`).
  2. Memastikan `device_id` dan `device_fingerprint` sesuai dengan rekaman aktivasi perangkat.
  3. Memeriksa status lisensi di tabel `licenses`. Jika lisensi `subscription` sudah melewati `expires_at` (dan di luar `grace_until`), server secara atomik mengubah status lisensi di D1 menjadi `expired` dan mengembalikan `403 LICENSE_EXPIRED`.
- **Idempotensi:** Aman dipanggil berulang kali (read + heartbeat update + lease signing).

**Request Schema:**
```json
{
  "activation_id": "act_01JDF8Y5M9N8B7V6C5X4Z3A2S1",
  "device": {
    "device_id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
    "device_fingerprint": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
    "app_version": "0.2.0"
  }
}
```

### 2.3 `POST /v1/licenses/deactivate`
Menonaktifkan perangkat yang sedang aktif dan melepaskan 1 slot perangkat (`active_devices_count - 1`) secara atomik. Mendukung dua skenario:
1. **Self-Deactivation:** Perangkat yang sedang aktif menonaktifkan dirinya sendiri menggunakan `Authorization: Bearer ssact_...`.
2. **Remote Lost-Device Deactivation:** Pengguna yang mencapai batas perangkat (`409 DEVICE_LIMIT_REACHED`) menonaktifkan perangkat lamanya yang hilang/rusak dengan menyertakan `license_key` dan `target_activation_id`.

- **Idempotensi:** Jika `target_activation_id` sudah berstatus `deactivated`, kembalikan `200 OK` dengan `already_deactivated: true` tanpa mengurangi `active_devices_count` dua kali.

**Request Schema:**
```json
{
  "device_id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "target_activation_id": "act_01JDF8Y5M9N8B7V6C5X4Z3A2S1",
  "license_key": "SSPRO-7K9M-4P2Q-8R6T-3W5Y",
  "reason": "user_initiated_switch_device"
}
```
*(Catatan: `license_key` hanya wajib jika header `Authorization: Bearer ssact_...` tidak tersedia, misalnya saat menonaktifkan perangkat lama dari layar aktivasi).*

**Response Schema (`200 OK`):**
```json
{
  "ok": true,
  "deactivated_activation_id": "act_01JDF8Y5M9N8B7V6C5X4Z3A2S1",
  "already_deactivated": false,
  "license_id": "lic_01JDF8W2A1B2C3D4E5F6G7H8J9",
  "device_limit": 2,
  "devices_used": 0,
  "deactivated_at": "2026-11-20T16:30:00Z",
  "server_time": "2026-11-20T16:30:00Z"
}
```

**HTTP Status Codes:** `200 OK`, `400 Bad Request`, `401 Unauthorized`, `404 Not Found`, `429 Too Many Requests`, `500 Internal Server Error`.

## 3. Administrative & Billing Integration Endpoints

Seluruh endpoint `/v1/admin/*` wajib menyertakan header:
`Authorization: Bearer ssadm_<key_id>_<secret>`
dan diverifikasi terhadap tabel `admin_api_keys` dengan role yang sesuai (`super_admin`, `support_admin`, `billing_system`).

### 3.1 `POST /v1/admin/licenses` (Issue / Create License)
Menerbitkan lisensi baru (`perpetual` maupun `subscription`). Plaintext `license_key` **hanya dikembalikan satu kali** pada respons pembuatan ini; database hanya menyimpan `key_prefix` dan `key_hash`.

- **Role yang Diizinkan:** `super_admin`, `billing_system`
- **Idempotensi:** Wajib menyertakan header `Idempotency-Key`.
- **Aturan Validasi:**
  - Jika `license_type == "perpetual"`: `billing_interval` wajib `"lifetime"`, `expires_at` wajib `null`.
  - Jika `license_type == "subscription"`: `billing_interval` wajib `"monthly"` atau `"yearly"`, `current_period_start`, `current_period_end`, dan `expires_at` wajib diisi dan `current_period_end > current_period_start`.
  - `device_limit` wajib bilangan bulat antara `1` dan `50` (default `2`).

**Request Schema:**

### 3.2 `GET /v1/admin/licenses/:license_id`
Mengambil detail lengkap lisensi, status langganan, daftar perangkat yang terikat, dan 50 event audit terakhir dari `license_events`.
- **Role yang Diizinkan:** `super_admin`, `support_admin`, `read_only`.

---

### 3.3 `PATCH /v1/admin/licenses/:license_id`
Mengubah `device_limit`, `plan_code`, `entitlements`, atau metadata pelanggan (`customer_email`, `notes`).
- **Role yang Diizinkan:** `super_admin`, `support_admin`.
- **Aturan Validasi:** `device_limit` tidak boleh diubah menjadi lebih kecil dari ` 1`. Jika `device_limit` baru lebih kecil dari `active_devices_count` saat ini, perangkat yang sudah aktif tetap berjalan kecuali `force_evict_excess_devices: true` disertakan.

---

### 3.4 `POST /v1/admin/licenses/:license_id/suspend` & `POST /v1/admin/licenses/:license_id/reinstate`
Membekukan sementara lisensi (`status = 'suspended'`) atau mengaktifkannya kembali (`status = 'active'`).
- **Role yang Diizinkan:** `super_admin`, `support_admin`.
- **Request Schema:**
  ```json
  {
    "reason": "Suspected credential leakage across multiple IPs",
    "revoke_active_sessions": false
  }
  ```

---

### 3.5 `POST /v1/admin/licenses/:license_id/revoke`
Mencabut lisensi secara permanen (`status = 'revoked'`), menonaktifkan seluruh aktivasi perangkat yang terikat (`status = 'revoked'`), mereset `active_devices_count = 0`, dan mencatat event `license_revoked` di `license_events`.
- **Role yang Diizinkan:** `super_admin`, `billing_system`.
- **Idempotensi:** Jika sudah `revoked`, mengembalikan `200 OK` tanpa error.
- **Request Schema:**
  ```json
  {
    "reason": "Order refunded / chargeback",
    "external_reference_id": "rfnd_998877"
  }
  ```

---

### 3.6 `POST /v1/admin/licenses/:license_id/renew` (Subscription Period Extension)
Memperpanjang periode aktif lisensi bertipe `subscription` berdasarkan pembayaran yang telah terkonfirmasi secara manual/backoffice.
- **Role yang Diizinkan:** `super_admin`, `billing_system`.
- **Aturan Validasi:**
  - Hanya berlaku untuk `license_type == "subscription"` (menolak `perpetual` dengan `400 INVALID_REQUEST`).
  - Wajib menyertakan `external_payment_id` / `idempotency_key` dan `new_period_end` ($> \text{current\_period\_end}$).

**Request Schema:**
```json
{
  "billing_provider": "manual_transfer",
  "external_payment_id": "inv_2027_11_20_001",
  "amount_minor": 99000,
  "currency": "IDR",
  "new_period_start": "2027-11-20T16:00:00Z",
  "new_period_end": "2028-11-20T16:00:00Z",
  "reason": "Confirmed annual bank transfer renewal"
}
```

---

### 3.7 `DELETE /v1/admin/licenses/:license_id/devices/:activation_id`
Melepaskan paksa (*force-deactivate*) satu perangkat dari lisensi tertentu (misalnya permintaan bantuan pengguna yang kehilangan PC).
- **Role yang Diizinkan:** `super_admin`, `support_admin`.

---

### 3.8 `POST /v1/billing/webhooks/:provider` (Provider-Independent Billing Webhook)
Endpoint masuk untuk adapter pembayaran eksternal (misalnya `stripe`, `lemonsqueezy`, `paddle`, `midtrans`, `xendit`).
- **Autentikasi:** Verifikasi tanda tangan kriptografis webhook spesifik provider (`X-Signature` / `Stripe-Signature` / `X-Callback-Token`) menggunakan secret di Cloudflare Secrets.
- **Perilaku:** Menormalisasi payload ke dalam `CanonicalBillingEvent`, menyimpan ke `billing_events` secara idempoten (`UNIQUE(provider, provider_event_id)`), dan hanya memperbarui `current_period_end` / `expires_at` pada `licenses` jika `canonical_event_type == "payment.succeeded"`.
